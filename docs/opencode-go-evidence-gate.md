# OpenCode Go evidence gate

OpenCode Go remains an empty admitted set and is not supported. This note records the boundary for
the source-only candidate evaluation and keeps published documentation aligned
with the implementation decisions D-01 through D-11.

The opt-in identity is `kind = "opencode_go"`, with
`SHUNT_OPENCODE_GO_API_KEY` and canonical destination
`https://opencode.ai/zen/go/v1`. The candidates are `glm-5.3-flash`,
`omen-alpha`, `muse-spark-1.3-contributor`, and `deepseek-v4-flash`; none is
supported or live-verified. Every explicit selection rejects before credential
lookup and dispatch. The empty admitted set emits neither a credential nor an
`x-opencode-session` header.

## Decision links

- **D-01** permits this additive, opt-in public identity without changing existing credentials.
- **D-02–D-03** require a table-driven exact tuple and pre-credential rejection.
- **D-04–D-05** keep four dated candidates and their unknown fields/provenance distinct.
- **D-06** makes zero admission valid and forbids dormant multi-wire dispatch.
- **D-07** requires reuse of the matching existing Chat contract and, only after promotion, a stable opaque conversation-scoped `x-opencode-session` sent to the canonical destination.
- **D-08** preserves bounded authoritative terminals, conservative retry, and cancellation ownership.
- **D-09** scopes isolated verification and protects production OpenCodex state.
- **D-10** requires synchronized README, site, and locale follow-up surfaces.
- **D-11** keeps live smoke separately opt-in and prohibits credential inspection or broad sweeps.

Promotion requires exact model, destination, wire, effort, and capabilities,
hermetic conformance, and credential-safe captured or live evidence together.
Unknown fields, family inference, wrong wires, unsupported effort aliases, and
permissive EOF repair remain rejected. The strict authoritative terminal policy
is part of the evidence gate, not a future compatibility promise.
