<behavior>CHAT-05/D-08. The unary machine accepts a chat.completion JSON body and emits the Anthropic response contract: text content, tool_use blocks when present, usage (input/output tokens), and stop_reason from finish_reason (stop→end_turn, length→max_tokens, content_filter→an explicit typed unsupported-finish gateway error (never an invalid Anthropic stop_reason), tool_calls→tool_use). An embedded provider error — payload error object, finish_reason "error", or a 200 status with an error-shaped body — surfaces as an Anthropic-shaped gateway error; an upstream request-id is forwarded only when the header name is on the existing redaction allowlist, otherwise it is dropped. A unary message reasoning_content string maps to an Anthropic thinking block with no fabricated signature; reasoning fields are provider extensions, not official Chat fields (13-PROTOCOL-EVIDENCE.md). A null or empty-string reasoning_content is treated as absent — no empty thinking block. If both reasoning_content and reasoning aliases appear with conflicting values the response fails closed; a lone supported alias is accepted. Unary JSON objects have no temporal field order: emit thinking, then text, then tools. Terminal validation at close inspects strictly the events accumulated in the current batch: a stream ending with a valid finish plus [DONE] succeeds; a stream ending without them fails with exactly one error — and that judgment is made only on received bytes, never by promising or predicting future bytes.
