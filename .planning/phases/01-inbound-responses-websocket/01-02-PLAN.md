<objective>
Implement full turn lifecycle management, prompt cancellation on replacement or disconnect, byte-faithful SSE-to-WebSocket relay stopping at the first terminal event, bounded streaming backpressure, safe response header filtering, and OpenAI-shaped error envelopes.

Purpose: Ensures that streaming turns execute with protocol fidelity, explicit memory bounds, leak-free cancellation, and strict header sanitization.
Output: Active turn supervisor with monotonic generation, abortable stream pump, backpressure-bounded socket sender, and safe header projection.

## must_haves
- Single active turn per socket: a replacement response.create aborts the previous turn and drops old frames (per D-04, WS-06).
- Socket disconnect immediately terminates upstream request task and releases account/concurrency leases (per D-04, WS-06).
- Upstream SSE data payloads forward unchanged until the first terminal event (completed, failed, incomplete) and stop reading (per D-03, WS-04).
- Safe header projection copies only allowlisted headers (retry-after, request ids, rate-limit, codex headers) and strictly strips cookies and credentials (per D-07, WS-05).
- Downstream socket sends are awaited to exert backpressure, with zero buffering of complete upstream responses (per D-06, WS-07).

## Prohibitions
- Do not buffer or collect a successful upstream SSE response.
- Do not forward client credentials, cookies, hop-by-hop headers, or internal Shunt headers upstream.
- Do not expose upstream cookies or arbitrary response headers in WS error frames.
- Do not add public config keys or alter documented provider selection semantics.
- Do not change credential-file writeback behavior.
- Do not add persistent history, a second pool, or a general response-repair framework.

## Artifacts this phase produces
- src/codex_endpoint/websocket.rs (turn supervisor, replacement abort, backpressure pump)
- src/codex_endpoint/frame.rs (safe header allowlist, error frame formatter)
</objective>

In src/codex_endpoint/websocket.rs, implement the session turn supervisor. Maintain a monotonic turn_id: u64 and an Option<tokio::task::JoinHandle<()>> representing the active turn task. The session loop must use tokio::select! over incoming client WebSocket frames and active turn events. When a new response.create frame arrives while an active turn is running (per D-04, WS-06):
1. Immediately abort the running turn's JoinHandle.
2. Increment turn_id so any pending or queued frames bearing the old generation are discarded.
3. Allow the dropped JoinHandle and dropped upstream response body to release their account pool reservation and concurrency lease via RAII.
4. Launch the new turn task stamped with the new turn_id.
When the client socket disconnects or closes:
1. Immediately abort the running turn task.
2. Drop all response body streams and release all account and concurrency permits.
3. Exit the session loop cleanly.
Ensure no mutex or channel holds an unbounded queue.
