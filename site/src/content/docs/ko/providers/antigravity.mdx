내장 **`antigravity`** 프로바이더는 HTTP를 통해 `daily-cloudcode-pa.googleapis.com`에 있는 Google의
**Antigravity** 백엔드에 도달합니다. 이 호스트는 Antigravity 클라이언트 자신이 디스커버리와 추론
양쪽에 사용하는 `daily-` 컨트롤 플레인입니다. `gemini` 프로바이더와 동일한 Code Assist 프로토콜을 사용하며 —
shunt는 Anthropic Messages를 `streamGenerateContent?alt=sse`로 변환합니다 — 다만
Antigravity 구독 토큰으로 인증하고 프로젝트 디스커버리 과정에서 자신을 `ideType: ANTIGRAVITY`로
식별합니다.

Antigravity에는 두 번째의 더 오래된 전송이 있습니다. `kind = "antigravity_cli"`는 로컬 `agy` 바이너리를
서브프로세스로 실행하며 **더 이상 사용되지 않습니다** —
[더 이상 사용되지 않는 `antigravity-cli` 전송](/ko/guides/providers/#더-이상-사용되지-않는-antigravity_cli-전송)을
참고하세요. 이 페이지는 그런 장치가 전혀 필요 없는 HTTP 프로바이더를 다룹니다.

<Aside type="caution" title="Antigravity 약관">

Google의 [Antigravity 약관](https://antigravity.google/terms)은 이 사용 방식을 직접 지목합니다. "서드파티 소프트웨어, 도구,
서비스로 서비스에 접근하는 것(예: OpenClaw를 Antigravity OAuth와 함께 사용)은 본 계약 위반"이며,
그러한 위반은 "Antigravity 및/또는 Gemini CLI 계정의 정지 또는 해지 사유가 될 수 있다"고 명시합니다.
shunt는 Antigravity OAuth를 사용하는 서드파티 소프트웨어이므로, 이 프로바이더로 라우팅하는 것은 그
조항에 그대로 해당합니다. 구독이 그 위험을 감수할 만한지는 본인의 판단이며, 여기 있는 어떤 것도 계정을
보호해 주지 못합니다.

</Aside>

## 네이티브 도구 기록

네이티브 OAuth 응답은 불투명한 `call_antigravity_v2_` 도구 ID를 사용합니다. 도구 결과를 보낼 때 ID, 도구 이름, 인수 및 기록 순서를 그대로 유지하세요. `call_gemini_v1_` ID는 비네이티브 Gemini에서는 계속 지원되지만 네이티브 Antigravity에서는 거부됩니다. 이전 네이티브 기록을 마이그레이션할 때는 새 대화를 시작하세요.

세션은 계정과 정규화된 첫 사용자 메시지에서 파생되므로 후속 요청에서도 유지됩니다. 같은 계정에서 동일한 첫 메시지는 세션을 공유합니다. 태그는 계정/세션과 각 호출의 업스트림 서명, 이름, 인수, 전체 대화 내 순번을 연결합니다. 이는 키가 없는 컨텍스트 검사이며 업스트림 출처의 암호학적 증명이 아닙니다. 의도적으로 다시 계산한 태그는 감지할 수 없습니다. 업스트림 서명은 합성 없이 보존되며 서명 캐시나 서명 키는 영구 저장되지 않습니다.

## 빠른 시작

코딩 에이전트가 대신 구성하도록 하세요 — `shunt add`는 내장된 설정 블루프린트를 출력합니다
(오프라인·읽기 전용이며, 구성은 에이전트가 편집하고 이 명령은 절대 편집하지 않습니다):

```bash
shunt add upstream antigravity --print | claude
```

또는 아래의 수동 단계를 따르세요.

## 1. 로그인

```bash
shunt login antigravity
```

이는 Antigravity 자체의 OAuth 클라이언트를 사용하는 Google authorization-code 플로우를 실행하고
`~/.shunt/antigravity-auth.json`을 기록하며, shunt는 이 파일을 읽고 자동 갱신합니다. 이 플로우는 다섯 개의
스코프를 요청합니다:

```text
https://www.googleapis.com/auth/cloud-platform
https://www.googleapis.com/auth/userinfo.email
https://www.googleapis.com/auth/userinfo.profile
https://www.googleapis.com/auth/cclog
https://www.googleapis.com/auth/experimentsandconfigs
```

마지막 두 개가 바로 **Gemini CLI 로그인을 여기서 재사용할 수 없고, 그 반대도 마찬가지인** 이유입니다:
`~/.gemini/oauth_creds.json` 토큰은 결코 `cclog`나 `experimentsandconfigs`를 담지 않습니다.
`google_oauth`와 `antigravity_oauth`는 서로 교체할 수 없습니다.

로그인은 Code Assist 프로젝트도 함께 해석하며 — 먼저 `loadCodeAssist`, 그다음 처음 사용하는 계정을
프로비저닝하기 위한 `onboardUser` — 프로젝트 id를 자격 증명 파일에 저장합니다. 첫 요청 앞에 디스커버리가
놓이지 않습니다. 디스커버리가 실패해도 로그인은 토큰을 저장하고 첫 요청에서 재시도합니다.

## 2. 업스트림 구성

프로바이더는 내장이므로, `provider = "antigravity"`를 지정한 `[[routes]]` 항목만으로 자체 프로바이더
테이블 없이 동작합니다. 순서가 있는 업스트림으로 선언하는 것은 다릅니다: **Antigravity 종류에는
`[[upstreams]]` 프리셋이 없으므로**, 거기서는 `provider = "antigravity"`를 쓸 수 없고 `kind`, `base_url`,
`auth`를 직접 설정해야 합니다:

```toml
[[upstreams]]
name = "anthropic"
provider = "anthropic"   # 라우트가 없는 모델(예: claude-*)의 기본값으로 Anthropic을 유지

[[upstreams]]
name = "antigravity"
kind = "antigravity"
base_url = "https://daily-cloudcode-pa.googleapis.com"
auth = "antigravity_oauth"
```

순서가 있는 `[[upstreams]]`는 shunt의 내장 프로바이더를 대체하므로, 명시적 구성은 여전히 폴백 대상인
`anthropic` 기본값도 함께 선언해야 합니다(`server.default_provider`의 기본값은 `anthropic`입니다).

레거시 `[providers.antigravity]` 테이블 형식도 계속 지원됩니다 — 다만 한 파일에서 `[[upstreams]]`와
`[providers.*]`를 섞지 마세요.

## 3. 정확한 카탈로그 모델 라우팅

네이티브 추론은 계정별 `fetchAvailableModels`의 최신 증거로 정확한 `upstream_model`을 확인해야 합니다. 크기가 제한된 카탈로그 스냅샷은 백엔드, 계정 지문, 프로젝트별로 구분됩니다. 성공한 캐시 항목은 10분 TTL 동안 유효하지만, 오래된 스냅샷이나 실패한 최초 조회로 추론을 허용하지 않습니다. 거부 전에 인증과 카탈로그 조회가 수행될 수 있지만, 지원하지 않는 조합은 추론에 도달하지 않습니다. 카탈로그 조회는 리디렉션을 거부하며, 구성된 엔드포인트의 증거만 추론 허용에 사용합니다.

정확한 Gemini 카탈로그 ID를 사용하세요. 접미사 추가, 가까운 effort 선택, 사라진 모델의 재지정은 하지 않으며 Claude/GPT 항목도 이 네이티브 어댑터로 전달하지 않습니다. 접미사 없는 ID를 다른 모델로 확장하지 않습니다. 카탈로그는 바뀔 수 있으므로 아래는 구성 예시이지 현재 제공 여부를 보장하는 목록이 아닙니다.

```toml
[[routes]]
model = "claude-gemini-via-antigravity"
provider = "antigravity"
upstream_model = "gemini-3.8-flash-high"
```

라우트/프로바이더의 `effort`가 요청의 `output_config.effort`보다 우선합니다. 명시한 effort는 접미사형 카탈로그 ID와 일치해야 합니다. 정확한 `-tiered` ID는 `generationConfig.thinkingConfig.thinkingLevel`에 `low`, `medium`, `high` 중 하나를 전달하며, 미지정 시 `medium`입니다. `xhigh`, `max`를 포함한 알 수 없는 값은 조용히 변환하지 않습니다. thinking budget은 생성 제어값으로 유지되며 다른 카탈로그 모델을 추측하는 데 사용하지 않습니다.

## 네이티브 전송과 복구

두 클라이언트 모드 모두 `streamGenerateContent?alt=sse`를 사용합니다. 스트리밍은 이벤트를 즉시 전달하며 비스트리밍만 제한된 크기로 누적합니다. 텍스트, 추론, 순서 있는 도구, 사용량, 종료 상태, 내장 오류를 하나의 검증된 디코더로 처리합니다. 잘못되거나 잘린 스트림, 불완전한 도구, 잘못되거나 중복된 종료는 오류로 처리합니다.

다운스트림 헤더나 출력 전의 최초 `401`에 한해 같은 계정의 메모리 내 갱신과 재전송을 한 번 허용합니다. 프로젝트, 카탈로그, 세션, 요청 ID, 본문은 동일하며 bearer만 바뀝니다. 두 번째 `401`, 갱신 실패, 계정 변경, 전송 여부가 불확실한 실패, 헤더/출력/도구 이후 오류에서는 재전송이나 프로바이더 전환을 하지 않습니다. 새 복구 경로는 자격 증명을 기록하지 않습니다. 기존 로그인/만료 갱신의 저장 동작은 그대로이며, 레거시 refresh-token 기반 신원이 바뀌면 거부합니다. 어느 모드에서든 취소하면 업스트림 본문과 요청 수용 슬롯이 해제됩니다.

증거는 2026-09-07의 합성 데이터 기반 격리 라우터/루프백 테스트이며 실시간 모델 제공을 보장하지 않습니다. Google AI Studio Web은 제외됩니다. 영구 서명 저장, 범용 캐시/저장소 플랫폼, 계정 간 프로젝트 재사용, 진행 없음 판단에 따른 취소 휴리스틱은 추가하지 않습니다.

## 어댑터가 전달하는 것

어댑터는 어시스턴트의 **텍스트**와 **thinking**을 Anthropic SSE로 스트리밍하고, 클라이언트의 **도구**를
네이티브로 브리지합니다: `tool_use`는 Gemini `functionCall`이 되고, `tool_result`는 `functionResponse`가
되며, 도구 선언과 도구 선택도 함께 변환됩니다. **시스템 프롬프트**는 `systemInstruction`이 됩니다. 토큰
사용량은 Google이 보고한 수치입니다 — `promptTokenCount`와 `candidatesTokenCount`가 `input_tokens`와
`output_tokens`에 매핑됩니다.

**Thinking**은 요청을 따릅니다. `thinking.type = "enabled"`는 `budget_tokens`(기본값 `1024`)로 `thinkingConfig.thinkingBudget`을 설정하고, `"disabled"`는 `0`으로 설정합니다.

모든 요청은 `model`, `project`, `userAgent: "antigravity"`, `requestType: "agent"`, 새 `requestId: "agent-<uuid>"`, `request.sessionId`를 전달합니다. 세션은 늘어나는 전체 기록이 아니라 위에서 설명한 계정과 정규화된 첫 사용자 메시지를 따릅니다. 일반 `gemini` Code Assist 엔벨로프는 변경되지 않습니다.

**도구 스키마는 Gemini의 `Schema` 방언에 맞게 조정됩니다** — 이 프로바이더와, 같은 어댑터를 쓰는 `gemini`
프로바이더 모두에서요. `$schema`, `$id`, `$comment`,
`propertyNames`, `patternProperties`, `exclusiveMinimum`, `exclusiveMaximum`, `const`는 제거되고, 그 외의
키워드는 작성된 그대로 전달됩니다. `type` 목록은 첫 번째 non-`null` 항목을 유지하며, 목록에 `null`이 있으면
`nullable: true`가 설정되고, `null`만 있는 목록은 nullable `string`이 됩니다. 배열이 아닌 모든
스키마 — 다른 멤버로 정해진 유니언이든, 평범한 스칼라든 — 는 `prefixItems`와 스키마 객체가 아닌 `items`를 버리고, 객체 값
`items`는 그대로 유지합니다. 타입 없는 스키마는 `prefixItems`나 배열 값 또는 객체 값 `items`를 가지면 배열로 취급되고,
그렇지 않으면 홀로 남은 불리언 `items`만 버립니다. 모든 배열은 단일 `items`
스키마로 전송됩니다: 튜플 — `prefixItems`, 또는 draft-07의 배열 값 `items` — 은 하나로 접히는데, 동일한
위치들은 그 스키마를 유지하고, 배열이 아닌 타입만 일치하는 위치들은 그 타입을 유지하며, 그 외에는 첫
위치의 스키마가 남습니다. `prefixItems` 옆에 타입이 선언된 `items` 스키마가 이미 있으면 그 스키마가 그대로
유지되고 위치들은 버려집니다. 타입이 `anyOf`/`oneOf`/`allOf` 분기 안에 있는 요소도 같은 방식으로 접힙니다.
요소에 대해 아무것도 말하지 않는 배열이나 요소 스키마가 타입을 선언하지 않는 배열은, 요소가 `enum`이나
`properties`로 타입을 암시하지 않는 한 `items: {"type": "string"}`으로 전송됩니다. 이 폴백은 요청을
거부하는 대신 요소 타입을 좁히므로, 튜플이 `string` 타입으로 도착하는 도구는 라우팅 오류가 아니라 이 조정이
동작한 결과입니다.

프로덕션 트래픽을 라우팅하기 전에 알아둘 만한 제한이 두 가지 있습니다:

- **이미지는 인라인이어야 합니다.** base64 `image` 블록은 Gemini `inlineData`가 됩니다. **URL 이미지
  소스는 `400`으로 거부됩니다**(`URL image sources are not supported by the Gemini adapter`).
- **도구 결과는 리치 미디어를 담을 수 없습니다.** 내용에 `image`나 `document` 블록이 포함된
  `tool_result`는 거부됩니다.

## 검증

```bash
shunt check    # -> config ok
shunt run
curl -sS http://127.0.0.1:3001/v1/messages \
  -H 'anthropic-version: 2023-06-01' \
  -H 'content-type: application/json' \
  -d '{"model":"claude-gemini-via-antigravity","max_tokens":16,"messages":[{"role":"user","content":"Reply with OK."}]}'
```

응답의 `x-gateway-upstream` 헤더가 `antigravity`를 가리키는지 확인한 다음,
[Claude Code를 shunt로 지정](/ko/guides/connect-claude-code/)하세요.

<Aside type="note" title="오버라이드">

`SHUNT_ANTIGRAVITY_AUTH_FILE`은 자격 증명 경로를 변경하며 빈 값이면 기본값을 사용합니다.

네이티브 추론은 정확한 표준 HTTPS 루트인 `https://daily-cloudcode-pa.googleapis.com` 또는 `https://cloudcode-pa.googleapis.com`을 사용합니다. 프로덕션 루트는 daily 컨트롤 플레인으로 정규화됩니다. 경로 접두사, 쿼리, 프래그먼트, 사용자 정보, 별도 프로덕션 포트는 설정하지 마세요. 루프백 루트는 로컬 프록시로 사용할 수 있지만 정확히 같은 오리진만 허용됩니다. 추론 리디렉션도 검증된 오리진과 정확한 SSE 경로/쿼리를 유지해야 하며, 유사 호스트나 다른 오리진은 bearer 전송 전에 거부됩니다.

[`shunt login antigravity`](/reference/cli/#shunt-login-antigravity)는 **라우팅된** Antigravity
업스트림을 상대로 — 또는 라우트를 아직 연결하지 않았다면 선언한 Antigravity 업스트림을 상대로 —
디스커버리를 수행합니다. 후보가 하나면 그대로 이기고, 여럿이 자격을 갖추면 **`antigravity`라는 이름의**
후보가 이깁니다. 여럿이 자격을 갖추었는데 그 이름을 가진 것이 없으면 로그인은 추측하기를 거부합니다 —
경고를 로그에 남기고 기본 엔드포인트로 폴백하므로, 프로비저닝하는 프로젝트가 라우트가 사용하는
백엔드의 것이 아닐 수 있습니다. 디스커버리 대상으로 삼고 싶은 업스트림의 이름을 `antigravity`로 지으세요.

</Aside>

<Aside type="caution" title="`antigravity`의 의미가 바뀌었습니다">

`kind = "antigravity"`는 예전에 로컬 `agy` 바이너리를 실행했습니다. 이제는 HTTP 업스트림이며, 서브프로세스
전송은 `kind = "antigravity_cli"`(내장 프로바이더 `antigravity-cli`)로 옮겨졌습니다.
예전 의미를 그대로 담고 있는 구성은 조용히 다른 대상으로 재지정되지 않고 이름을 근거로 거부되며, 자격 증명
없이 라우팅된 `antigravity` 프로바이더는 기동을 거부합니다:

```text
provider `antigravity` is routed but has no credential. It is now the native HTTP upstream, not the
local `agy` CLI. Run `shunt login antigravity` to authenticate it, or route to `antigravity-cli` to
stay on the deprecated subprocess transport.
```

[`shunt check`](/ko/reference/cli/#shunt-check)도 동일한 가드를 오프라인으로 실행하므로, CI가 롤아웃 전에
잘못된 구성을 잡아냅니다. 이 검사는 **존재 여부만** 확인합니다 — 자격 증명을 열지 않으므로 비어 있거나
오래된 파일도 통과한 뒤 요청 경로에서 실패합니다.

</Aside>
